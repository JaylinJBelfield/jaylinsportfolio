Hardware Engineering Project

Custom Computing & Hardware

A collection of custom computer builds, OEM conversions, GPU integration experiments, cooling solutions, CAD work, and 3D-printed components designed to solve hardware problems that off-the-shelf parts do not.

Project Story

PC building became much more interesting to me once the builds stopped being standard. This project documents the systems where I have had to adapt server hardware, design custom components, troubleshoot platform limitations, and create physical solutions around the computer rather than simply assemble compatible retail parts.

Building Beyond Standard PCs

This project collects the hardware work that does not fit into a normal 'PC build.' I regularly repurpose OEM desktops, server components, laptop hardware, and accelerator GPUs into systems they were not originally designed to support.

That work requires more than choosing compatible parts. I often have to solve mounting, cooling, power, airflow, PCIe, firmware, and chassis problems before the system can operate reliably.

Custom Cooling for Datacenter GPUs

Passive datacenter GPUs such as Tesla accelerators expect server-grade airflow instead of carrying their own fans. I experimented with quieter ways to recreate that airflow in workstation-style systems.

This led to custom duct concepts that direct fan pressure through the GPU heatsink while working around limited rack space, unusual card placement, and noise constraints.

  • Passive GPU cooling
  • Airflow direction
  • Fan sizing
  • Thermal constraints
  • Rack-space limitations

Designing Custom Components

When an existing bracket, duct, or mounting point does not fit the build, I design replacement components and prototype them with 3D printing. PETG-CF is useful for parts that need more stiffness and heat resistance than decorative prints.

Recent examples include GPU airflow ducts and custom support/mounting concepts for OEM heatsinks that originally relied on the computer chassis for threaded mounting points.

Problem → measure → model → print → test → revise is the same engineering loop I use in software, applied to physical hardware.

PCIe and Accelerator Integration

I have tested enterprise and consumer GPUs across systems that were not built as dedicated AI servers. That has exposed real compatibility problems involving PCIe lane layouts, firmware behavior, BAR allocation, IOMMU messages, power delivery, drivers, and boot failures.

Instead of only reading hardware specifications, I use the failures to learn how motherboard design and platform limitations affect what a GPU can actually do.

Repurposing Existing Hardware

A recurring theme in my builds is extracting more value from hardware that already exists. Small desktops become virtualization nodes, workstation boards become AI experiments, and older systems become infrastructure appliances instead of being discarded.

This approach keeps the builds cost-conscious while giving me experience troubleshooting proprietary layouts, unusual connectors, limited expansion, and mechanical constraints.

What This Project Taught Me

Hardware problems rarely stay in one category. A GPU compatibility issue can involve firmware, PCIe topology, power, cooling, drivers, and physical fit at the same time. Working through those interactions has made me much more comfortable troubleshooting systems from the operating system all the way down to the chassis.

Custom fabrication has also changed how I approach problems: if the correct bracket, duct, or mount does not exist, I can design a part around the actual constraints instead of abandoning the build.
