Infrastructure & Networking Project

Grim Grid Homelab

A portable private-cloud and homelab environment built around networking, remote management, virtualization, shared storage, monitoring, hosted services, Raspberry Pi infrastructure, and local AI compute.

Project Story

Grim Grid is the project that transformed my understanding of computers from individual machines into a connected infrastructure environment. I can now reach, monitor, and manage the systems from anywhere while keeping services organized across dedicated compute, storage, network, and monitoring roles.

From Computers to an Infrastructure Environment

Grim Grid began as a portable homelab and became the environment where I learned to operate multiple computers as one manageable system. It now combines virtualization, storage, monitoring, networking, AI compute, Raspberry Pi services, and hosted applications inside a rack I can administer locally or remotely.

The important part is not simply owning several machines. The project is about making those machines discoverable, reachable, monitored, organized, and useful as shared infrastructure.

Networking and 24/7 Remote Management

Networking became one of the biggest learning areas in this project. I built a dedicated local network, assigned predictable addressing, configured DNS services, connected managed switching, and standardized remote administration across the rack.

Tailscale gives me secure access to machines and management sites when I am away from the rack. Web interfaces and SSH let me reach Proxmox, TrueNAS, monitoring, hosted services, and other systems from my laptop instead of needing physical access.

  • Managed 2.5GbE switching
  • DHCP reservations and predictable addressing
  • Pi-hole and Unbound DNS
  • Tailscale remote access
  • SSH administration
  • Service dashboards and web management
  • SNMP and node telemetry

Virtualization and Hosted Services

The Lenovo Tiny nodes run Proxmox and provide a flexible layer for virtual machines and containers. This lets me isolate services, test new systems safely, and assign CPU, memory, and storage resources based on the workload.

Services hosted through the environment include home automation and a managed Minecraft deployment with a separate control service, remote tunnel access, idle shutdown, and restart protection.

TrueNAS and Shared Storage

A dedicated TrueNAS system provides shared storage for AI workspaces, services, backups, logs, personal files, media, and AI models. I separated the storage into purpose-specific pools and datasets so active workloads, AI data, and archival data can be managed differently.

SMB shares, users, groups, and ACLs allow different machines and AI workers to reach the data they need without treating the entire NAS as one unrestricted drive.

  • ZFS mirrors
  • SMB shares
  • Dataset planning
  • Users and groups
  • ACL permissions
  • Shared AI storage

Monitoring, Uptime, and Observability

A Raspberry Pi monitoring node runs Grafana, Prometheus, and Uptime Kuma so I can see whether systems are reachable and how they are performing. Node exporters and SNMP extend monitoring beyond one computer to the larger rack.

The rack touchscreen is also being developed into a physical operations console where monitoring is only one module alongside quick controls, service navigation, Home Assistant, and Unara.

Dedicated Infrastructure Roles

The Raspberry Pis are assigned focused infrastructure jobs instead of being used as general-purpose computers. One handles DNS and ad blocking, another hosts monitoring and kiosk services, and another is used for retro gaming experiments.

Giving each device a clear role helped me learn service separation, Linux administration, Docker deployment, DNS troubleshooting, and the value of infrastructure that can keep running independently.

What This Project Taught Me

Grim Grid revolutionized my understanding of networking because I had to make many different systems communicate reliably instead of configuring one computer at a time. Addressing, DNS, switching, remote access, service ports, hostnames, monitoring, and troubleshooting all became practical problems instead of textbook concepts.

It also taught me that good infrastructure should be easy to operate. The end goal is not a rack that only works when I am standing beside it, but a network of systems with clear management interfaces, uptime monitoring, remote shell access, and secure 24/7 access from wherever I am.
