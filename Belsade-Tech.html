Belsade Tech: building infrastructure before the company is fully grown.

Belsade Tech is my long-term technology company project centered around servers, hosting, AI infrastructure, cybersecurity, virtualization, documentation, and business leadership. The project is not just a website or a single server rack. It is my attempt to build the foundation of a real technology company from the ground up while learning every layer: legal structure, operations, networking, hardware, Linux, virtualization, storage, services, and how to lead people around a technical vision.

The Infrastructure Foundation

The technical core of Belsade Tech is a rack-based infrastructure environment. I wanted to learn what it actually means to operate technology at a systems level, not just write code and deploy it somewhere I do not understand.

Rack-Based Private Cloud Direction

The rack is being designed like a small, portable datacenter. Instead of treating each server as a random machine, I started organizing the environment by roles: internal compute, operations/control, public-facing gateway services, storage, management, and future GPU compute.

This taught me that infrastructure is not just about owning servers. The real work is deciding what each machine is responsible for, how traffic should move, what should be isolated, what should be exposed, what should be backed up, and how the environment should grow without becoming messy.

  • Dell PowerEdge and HP ProLiant rack servers used for compute and infrastructure roles.
  • Proxmox used as the virtualization layer for running virtual machines and services.
  • Rack planning around power, cooling, cable routing, storage, and future expansion.
  • Server role planning for internal workloads, DMZ services, control systems, and future GPU nodes.

Networking, Firewalling, and Segmentation

One of the biggest parts of Belsade Tech has been learning how to build a network that acts more like an enterprise environment than a normal home setup.

From “internet connection” to network architecture

I learned that a real infrastructure environment needs much more than basic Wi-Fi or a single flat network. Belsade Tech uses a firewall-first mindset where traffic should be routed, separated, and controlled based on what type of device or service is involved.

The network plan includes multiple segmented zones such as internal systems, management, DMZ, storage, GPU/AI workloads, learning devices, tenant services, backup systems, and observability. The purpose is to make the environment safer, easier to reason about, and closer to how production infrastructure is planned.

  • pfSense used as the firewall and router for the rack environment.
  • VLAN segmentation designed around a structured 10.79.x.x addressing plan.
  • Managed switch configuration for trunks, access ports, and network separation.
  • DMZ planning for services that may eventually face the public internet.
  • DHCP reservations used for centralized address management and portability.
  • DNS and routing concepts studied for future internal services and hosting goals.

Virtualization, Linux, and Service Deployment

Belsade Tech is also where I started connecting hardware to actual software services. The goal is not just to collect machines, but to run useful systems on them.

Proxmox and Virtual Machines

Proxmox is the main virtualization platform I am using to turn physical servers into flexible compute resources. Instead of installing one operating system and one service per server, Proxmox lets the hardware become a host for multiple virtual machines and containers.

This gives Belsade Tech a foundation for hosting internal tools, test environments, development servers, monitoring systems, AI experiments, web services, and future customer-facing workloads. It also helps me understand snapshots, storage pools, virtual networking, bridges, resource allocation, and the difference between physical and virtual infrastructure.

Linux Administration

I use Linux and Ubuntu systems to practice server administration, package management, terminal workflows, service configuration, remote access, and the kind of command-line work that supports real infrastructure.

Containers and Docker

Docker fits into the long-term plan because many modern services are deployed as containers. Learning Docker helps me think about repeatable deployments, service isolation, and hosting applications more cleanly.

Storage, RAID, and Reliability

Storage planning became a major part of the project because servers are only useful if data is organized, protected, and available. I worked with enterprise storage concepts such as RAID, mirrored drives, server drive bays, controller configuration, and the difference between boot drives, data drives, and shared storage.

This helped me think about failure. If a drive fails, what happens? If a server needs a clean reinstall, what must be preserved? If a service becomes important, where should its data live? These questions pushed the project toward a more serious infrastructure mindset.

  • RAID mirror concepts and drive failure testing in a lab environment.
  • Enterprise SATA SSD research for Proxmox boot and workload storage.
  • Planning around storage servers, backup systems, and future JBOD expansion.
  • Separating operating system drives from data/workload drives.

Cybersecurity and Infrastructure Safety

Since Belsade Tech is meant to eventually support real services, security has to be part of the foundation instead of something added later.

Firewall Rules

The firewall is treated as the main control point for traffic between networks. This includes deciding which VLANs can talk to each other, what services should be exposed, and what should stay locked down.

  • Internal network restrictions
  • Management access control
  • DMZ exposure planning

DMZ Planning

Public-facing services should not live directly beside internal systems. The DMZ concept helps separate services that may face the internet from private infrastructure that needs stronger protection.

  • Gateway/API entry planning
  • Public service isolation
  • Future reverse proxy or firewall service nodes

Remote Access

Remote access matters because infrastructure should be manageable without constantly being physically next to the rack. Tools like Tailscale fit into the long-term plan for secure remote management.

  • Private remote access
  • Administrative network separation
  • Controlled management paths

Business, Leadership, and Company Building

Belsade Tech is not only a hardware project. A major part of it has been learning how to think like a founder and build the structure around a company, not just the technology inside it.

Founder Responsibilities

Building Belsade Tech forced me to think about what it means to lead a technical project as a company. That includes setting direction, explaining the vision to others, organizing work, planning documentation, thinking about roles, and making decisions before everything is fully figured out.

I worked on the business foundation by thinking through LLC setup, internal documentation, onboarding systems, consultants, meetings, presentations, brand direction, employee roles, and how future contributors could understand what Belsade Tech is trying to become.

  • Company structure and LLC planning.
  • Employee onboarding documentation and early contributor expectations.
  • Consultant conversations and technical presentation practice.
  • Founder decision-making around direction, branding, and service focus.
  • Marketing and website planning for Belsade Tech’s public identity.

Documentation and Internal Systems

One of the less flashy but most important parts of Belsade Tech has been documentation. I started building governance-style documents, onboarding guides, role descriptions, expectations, and internal structures because I realized that a company cannot depend only on ideas in one person’s head.

Documentation turns a personal project into something other people can understand. It creates a place where expectations, responsibilities, project direction, and technical decisions can be written down. That matters if Belsade Tech eventually grows into a team with employees, partners, consultants, or clients.

How the Project Has Evolved

Belsade Tech has grown in stages. Each stage taught me a different part of running and building a technology company.

Stage 1

Hardware Research and Server Collection

The project began with researching enterprise servers, used hardware value, storage options, power needs, and how to get the most out of affordable equipment. This stage was about learning what server hardware is, what different models can do, and how to think about performance, memory, storage, and expansion.

Stage 2

Rack Planning and Network Bring-Up

After the hardware side started taking shape, the focus shifted toward building the rack as a real environment. That included pfSense, managed switching, VLANs, firewall rules, IP planning, management networks, and getting the servers to communicate in a structured way.

Stage 3

Virtualization and Services

The next stage focused on using Proxmox, Linux, Ubuntu, virtual machines, containers, storage, DNS concepts, and service deployment. This is where the rack started becoming less about hardware ownership and more about running actual systems.

Stage 4

Company Structure and Long-Term Platform Vision

As the technical side grew, the business side became more important. Belsade Tech expanded into documentation, onboarding, service planning, leadership, marketing, and the long-term idea of becoming an infrastructure and AI platform supporting multiple projects.
